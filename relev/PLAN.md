## 1. 포지셔닝과 경쟁 서비스 분석

### 1.1 한 줄 포지셔닝

**화장품에 성분 데이터베이스가 있듯, 피부관리 기술에도 데이터베이스가 필요하다.**
RE:LEV는 홈 뷰티 디바이스와 피부과 시술을 *상품명이 아니라 작용 기전*으로 분류하고, 둘 사이를 같은 기준으로 연결하는 독립 정보 플랫폼이다.

| 구분 | 내용 |
|---|---|
| 누구를 위해 | 디바이스 구매 · 시술을 고민하는 20–40대 여성 뷰티 소비자 (확장: 피부관리 관심층 전체) |
| 무엇을 | 기술 · 성분 · 기전 · 스펙 · 비용 · 근거 수준을 구조화한 데이터와 비교 도구 |
| 무엇과 다르게 | 순위 · 후기 · 가격 중심이 아니라, 기전 · 근거 · 출처 수준 중심 |
| 왜 믿을 수 있나 | 모든 값에 출처 등급과 검수일, 공개되지 않은 값은 "미공개"로 표시, 광고와 평가 분리 |

### 1.2 경쟁 · 인접 서비스 지형 (정성 분석, 수치 검증 필요)

| 유형 | 예시 | 강점 | RE:LEV가 비어 있다고 보는 지점 |
|---|---|---|---|
| 시술 가격 · 후기 플랫폼 | 강남언니, 바비톡 | 병원 · 가격 · 후기 탐색, 예약 동선 | 시술의 기전 · 성분을 상품명 단위로 깊게 구조화하지 않음. 홈케어와 연결 없음 |
| 화장품 성분 · 리뷰 앱 | 화해, 글로우픽 | 성분 DB 구조화, 리뷰 | 디바이스 · 에너지 기반 기술은 범위 밖 |
| 뷰티 커머스 | 올리브영, 브랜드몰, 쿠팡 · 네이버쇼핑 | 구매 편의, 프로모션 | 제조사 마케팅 용어를 그대로 노출, 기술 간 동일 기준 비교 어려움 |
| 유튜브 · 블로그 리뷰 | 뷰티 크리에이터 | 신뢰감, 사용 장면 | 협찬 여부와 근거 수준이 섞여 있음, 구조화된 데이터 아님 |
| 해외 성분 DB | INCIDecoder, Skinsort | 성분 단위 데이터 구조, SEO | 한국 디바이스 · 시술 시장 미반영 |
| 해외 시술 정보 | RealSelf, DermNet | 시술 백과 · 후기 | 한국 상품명 · 장비 체계와 다름 |

**결론**: 시술 플랫폼은 "어디서 얼마에", 성분 앱은 "무엇이 들었나", 커머스는 "무엇을 살까"를 답한다. **"이 기술이 내 피부에 무엇을 하는가, 홈과 클리닉은 어떻게 다른가"** 를 같은 기준으로 답하는 곳은 비어 있다는 것이 사업 가설이다 → 사용자 인터뷰 · 검색 키워드 볼륨으로 검증 (14장).

## 5. 주요 사용자 여정

**A. 홈 디바이스 입문자** — "고주파 기기 사도 될까?"
검색 유입(`RF 미세전류 차이`) → SCIENCE 기술 페이지 → 같은 기술 태그의 DEVICE 목록 → 제품 상세에서 공개/미공개 스펙 확인 → 2개 비교 → (P3) 구매 링크.
*성공 신호*: 기술 페이지 → 제품 상세 이동률, 비교 사용.

**B. 다중 디바이스 보유자** — "기기가 4개인데 언제 뭘 썼는지 모르겠다"
(P1) MY DEVICES 등록 → 제조사 권장 사용 간격 확인 → ROUTINE 기록. 병행 사용 추천은 하지 않음.

**C. 시술 입문자** — "써마지랑 올리지오가 뭐가 달라?"
CLINIC 시술 상세 → 둘 다 '모노폴라 RF' 계열이라는 구조 확인 → 시술↔시술 비교(성분 · 기전 · 회복 · 위험은 의료진 상담 필요 표기) → 관련 홈 RF 기술로 이동해 차이 이해.

**D. 고관여 소비자** — "이 기기 MHz랑 W/cm²가 진짜 의미 있는 숫자야?"
제품 상세 스펙 표 → 단위 해설(SCIENCE/units) → 측정 조건이 같은 값끼리만 비율 계산되는 비교 엔진.

**E. 브랜드 · 의료기관** — "우리 기술을 정확하게 알리고 싶다"
ABOUT의 데이터 제출 · 수정 요청 → 출처 등급 심사 → 공식 스펙 등재. 광고 상품(스폰서 콘텐츠)은 별도 표기, 평가 · 순위와 분리.

**HOME → CLINIC 핵심 여정**: 홈 RF 기기 상세 → "같은 기술 계열의 전문 시술" 카드 → 시술 상세 → 비용 계산기 → (필요 시) 의료진 상담. 플랫폼은 방문을 권하지 않고 차이를 설명한다.

## 6. 데이터베이스 구조 및 필드 정의

### 6.1 엔티티

```
Technology (기술)           id, name, family, aka[], summary, plain, mechanism, purposes[], evidenceNote, safety[], sourceIds[], reviewedAt
Device (홈 디바이스)         id, name, brand, model, maker, year, image, techIds[], makerTechName, specs{}, modes[], areas[], cautions[], certifications[], studies[], price{}, consumables{}, warranty, relatedTreatmentIds[], sourceIds[], reviewedAt, status
Treatment (시술)            id, name, kind(device|injectable|surface), equipmentOrProduct, maker, techIds[], ingredients[], mechanism, delivery, targetLayer{}, purposes[], approval{}, process, recovery, risks[], individualVariation, needsClinician[], priceSurvey[], relatedDeviceTechIds[], similarIds[], sourceIds[], reviewedAt, status
Source (출처)               id, tier, title, publisher, url, accessedAt
PriceObservation (가격 조사)  targetId, amount, currency, channel, observedAt, sourceId     ← 정가/판매가/시술가 구분
ChangeRequest (수정 요청)     targetId, field, proposedValue, evidenceUrl, submittedAt, state
```

### 6.2 값 단위 규칙 — 스펙은 숫자가 아니라 "출처가 붙은 관측값"

```json
"rfFrequency": {
  "status": "disclosed | undisclosed | unentered | unverified",
  "value": 1.0, "unit": "MHz",
  "condition": "측정 조건 (예: 최대 모드, 무부하)",
  "quantity": "frequency | power | current | energyDensity | area | pulseWidth | wavelength",
  "sourceId": "src-...", "checkedAt": "2026-11-18"
}
```

- `status`가 `disclosed`가 아니면 화면에 값 대신 "미공개 / 미입력 / 검수 필요"를 표시한다. 추정값을 넣는 필드는 없다.
- `quantity` + `unit` + `condition`이 모두 같을 때만 비교 엔진이 비율을 계산한다 (9.5 원칙).

### 6.3 출처 등급 (tier)

| tier | 의미 |
|---|---|
| T1 | 규제기관 · 공식 허가 문서 (식약처, FDA 등) |
| T2 | 동료 검토 학술 논문 |
| T3 | 독립 시험기관 자료 |
| T4 | 제조사 인체적용시험 |
| T5 | 제조사 공식 스펙 |
| T6 | 광고성 설명 |
| T7 | 사용자 경험 |

### 6.4 레코드 상태

`draft`(초안) → `reviewed`(편집 검수) → `expert-reviewed`(전문가 검수, P2). 프로토타입의 모든 레코드는 `draft`.

## 7. 기술 분류 체계

```
ELECTRICAL   ems · microcurrent · electroporation · iontophoresis(galvanic 포함)
RF           rf-monopolar · rf-bipolar · rf-multipolar · rf-other
ULTRASOUND   us-nonfocused · us-multifreq · hifu(집속)
LIGHT        led-red · led-nir · led-blue · ipl · laser
OTHER        plasma · cooling · heating · vibration · suction · combo
INJECTABLE   ha-filler · caha · plla · pdlla · pn-pdrn · ha-booster · toxin · other
SURFACE      chemical-peel · microneedle · laser-resurfacing · other
```

규칙
1. 한 제품 · 시술은 복수 태그 가능.
2. 제조사 고유 기술명(예: 상표화된 초음파 기술명)은 `makerTechName`에 별도 저장하고, 일반 기술 태그와 동일시하지 않는다.
3. 같은 태그 ≠ 같은 효과 · 안전성. 태그는 "같은 물리 원리 계열"만 의미한다.
4. 홈 ↔ 클리닉 연결은 태그 계열로만 만들고, 대체 가능성을 의미하지 않는다고 매번 표기.

## 8. 모바일 · 데스크톱 UI 디자인 방향

- **모바일 우선**: 검색 유입 대부분이 모바일이라는 가정. 상세 페이지는 한 컬럼, 스펙 표는 "라벨 / 값 / 출처 등급" 3단 행으로 접힘 없이 세로 스택.
- **데스크톱**: 목록은 좌측 분류 필터 + 우측 카드 그리드, 상세는 본문 + 우측 고정 "요약 패널(기술 태그 · 근거 등급 · 검수일 · 비교함 담기)".
- **정보 신뢰 UI**: 모든 값 옆 출처 등급 배지(T1–T7), "미공개" 칩은 회색 점선 — 비어 있음을 숨기지 않는다.
- **광고 분리**: 스폰서 콘텐츠는 라벤더가 아닌 별도 테두리 + "광고" 라벨, 데이터 화면에는 노출하지 않음.
- **비주얼 모티프**: 피부 단면 도식(표피 · 진피 · 피하지방 · SMAS 층)에 기술별 "알려진 표적 층"을 *범위*로 표시하되, 제품별 검증 전에는 "일반적인 설명"이라고 라벨링.
- 병원 홈페이지의 파란 톤, 쇼핑몰의 핑크 · 배너 과밀을 피한다.

## 9. 상세 페이지 구조

### 9.1 제품 상세 (DEVICE)
1. 헤더 — 제품명, 브랜드, 기술 태그, 레코드 상태, 마지막 검증일

3. 스펙 표 — 주파수 · 파장 · 전류 · 출력 · 에너지 밀도 · 면적 · 모드 · 강도 단계 (각 값에 출처 등급 / 미공개 표시)

5. 허가 · 인증 — 범위까지 명시 (예: "공산품" / "의료기기 n등급, 허가 목적: ...")
6. 근거 — 인체적용시험 vs 독립 연구를 분리
7. 비용 — 정가, 확인된 판매가(날짜), 소모품, 보증
8. HOME → CLINIC — 같은 기술 계열 시술 카드 + "대체를 의미하지 않음"
9. 출처 목록 · 수정 요청

### 9.2 시술 상세 (CLINIC)
1. 헤더 — 시술명, 장비 · 제품명, 제조사, 분류
2. 기전 — 에너지 전달 방식 또는 주요 성분, 적용 층
3. 허가사항 — 허가 목적과 범위
4. 일반적인 과정 · 예상 회복 — "개인차 있음"
5. 알려진 위험 · 부작용 — 축약 없이
6. 의료진 판단이 필요한 사항 — 고정 블록
7. 가격 조사 — 조사일 · 표본 · 채널 명시 (프로토타입에는 없음)
8. 관련 홈 기술 · 유사 시술
9. 출처 · 검수일

## 10. 비교 UX

- **비교함**: 어떤 상세 페이지에서든 "비교에 담기" → 하단 플로팅 바(최대 3). 종류가 섞여도 됨.
- **비교 표**: 공통 필드만 행으로. 한쪽만 있는 값은 "해당 없음", 없는 값은 "미공개".
- **제품 ↔ 시술 비교** 상단에 고정 안내: "같은 기술 계열이어도 출력, 표적 깊이, 허가 목적, 시술자가 다릅니다. 이 표는 효과의 크기를 비교하지 않습니다."
- **출력 비교 엔진**: `quantity · unit · condition` 일치 시에만 "A의 측정값은 B의 x%" 표시 + "물리적 출력 비율 ≠ 효과 비율". 불일치 시 왜 비교하지 않는지 사유를 보여 준다.
- **비용 계산기**: 사용자가 직접 입력(디바이스가 · 소모품 · 사용 기간 · 시술 1회가) → 단순 구매비용 손익분기 횟수. "효과 동등성을 가정하지 않은 단순 산수"를 계산 결과 바로 아래에 표시. "시술 1회 = 디바이스 n회" 계산은 제공하지 않는다.
